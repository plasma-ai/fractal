## Resume Mode

This node was paused mid-run and has been resumed (`$RESUME_MODE` is `true`);
the run continues where it left off -- same budgets, same iteration count. The
worktree was **not** cleaned: uncommitted changes are the frozen mid-step state
from before the pause (possibly from another machine). If your session carries
the interrupted context, simply continue the work in progress. If this is a
fresh session, re-orient within the current assignment's read and write
boundaries: inspect permitted uncommitted work, your own memory (`$MEMORY_DIR`),
prior plans in `$PLANS_DIR`, and relevant project wiki material (`$WIKI_DIR`)
only where permitted. A frozen subject remains the input; do not substitute live
working-tree content or browse excluded material to recover context. Adopt the
partially completed work and carry it forward -- do not restart it.

Where mailbox access is allowed, your prompts may also carry a harness re-read
of unread inbox headers. Read permitted directives before executing a replayed
decision -- especially spawns, which a countermand may have barred. Sealed
mailboxes stay sealed; resumption does not authorize opening excluded message
channels or broadening the commissioned read set.
